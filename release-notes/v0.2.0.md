Every cluster now has its own query library — so a query written for one cluster never runs on another by mistake.

- Queries, folders and workspace tabs belong to one cluster; switching the connection tab switches the whole workspace
- Import queries from another cluster on purpose: pick them, and independent copies (with their folder path) land in this cluster
- A safety net in the app core refuses to run a saved query on a cluster it doesn't belong to — even running a dev query on prod by accident is blocked
- The library header shows which cluster you're in, with a prod badge on production clusters; ⌘K and saved-query lists follow the active cluster
- Your existing library is migrated automatically: each query goes to the cluster it last ran on

**Install:** download `kabanos-mac-arm64.dmg` (Apple silicon) or `kabanos-mac-x64.dmg` (Intel). This build isn’t notarized yet: on first launch open System Settings → Privacy & Security → Open Anyway.
